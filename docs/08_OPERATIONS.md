# 部署、运维与回滚

生产固定单worker；不要直接启动历史AMI或E入口。默认Add4、Search8、LLM8、Embedding4；用户请求按用户锁保护。使用外部私有env和持久数据库，Nginx提供TLS和长请求超时。

## 当前已核验部署

`ami-v4.service` 使用 `/opt/aml/v4-rc1-20261027`，数据库 `/var/lib/ami-v4/memory.sqlite3`，本机8014端口。三个已提交端点均转发至该服务。当前线上核心不因发布包整理而改变。

保留P2服务用于回滚。若需切换，先停止平台评测并等待在途请求结束，保留当前配置和数据库的一致性备份，再把Nginx路由整体切到实际P2监听端口；执行 `nginx -t` 成功后reload。随后验证health和Search方法身份。不能只改一条接口，也不能在同一正式评测中把方法混用。V4和P2数据库各自保留，不互相覆盖；回滚后须使用新的评测任务。

备份SQLite应使用backup接口或停止写入后完整处理主库/WAL；不能单独复制正在写入的主库。当服务停止或异常重启，依靠持久化和同request_id幂等重试继续，不能把数据库恢复到丢失最新写入的旧快照。
